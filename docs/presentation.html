Slide 02 of 05 • Architecture & Technology

Serverless Google Cloud Architecture for Lean Teams

Designed for minimal operational effort, zero idle cost, and instant scaling from quiescent states to 100+ concurrent agent investigations during network incidents.

Compute & Runtime Choices

  • Cloud Run (FastAPI + MCP Server): Serverless container execution scaling 0 to 100 instances in < 2s. Eliminates GKE control-plane maintenance for a small team.
  • Cloud Run Jobs: Executes scheduled hourly inventory reconciliations and bulk batch imports without persistent idle infrastructure.
  • Cloud Pub/Sub: Absorbs 15-minute bursts of 50M performance counters arriving from vendor EMS (~20,000 rows/sec burst).

Tiered Polyglot Storage

  • Google BigQuery: 50M counter rows/day partitioned by date/customer, clustered by entity ID. Sub-second analytical queries.
  • Cloud SQL (PostgreSQL) / AlloyDB: Master entity metadata & bi-temporal valid_from/valid_to transaction intervals.
  • Memorystore Redis: Adjacency sub-graph cache guaranteeing < 2.0s p95 SLA for 2-hop topology traversals.
  • Firestore: Active agent session state, HITL proposals, and immutable governance audit trails.
Slide 03 of 05 • Data Modeling & Truth

Bi-Temporal Topology & Evidence Quality Certification

Eliminating the twin perils of autonomous AI operations: historical state corruption and mistaking missing telemetry for physical network degradation.

Bi-Temporal Timeline

Every node and edge record tracks two distinct temporal timelines:

  • Valid Time: The physical reality interval in the network.
  • System Time: The platform transaction ingestion interval.
  • Enables exact historical replay: "What did the topology look like at 10:05 UTC when alarms fired?" even if corrected vendor inventory arrived at 10:45 UTC.

Evidence Integrity Certification

Scenario Completeness Verdict Agent Action Boundary
Cells 001..003 100% (3/3) GENUINE_OUTAGE Permitted to stage reroute
Control Cell 099 33% (1/3) DATA_GAP_UNCERTAINTY Halt & decline remediation

AI agents are hard-coded to refuse destructive network mutations if evidence completeness is < 80%.
